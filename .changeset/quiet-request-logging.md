Optional, redacted request logging (D1) in the new `@sokpheak/sp-laravel-api/logging` subpath. `createLogger({ sink, mode?, maxBodyLength? })` is passed as `createApi({ logger })`; calls opt in with a per-call `log: true | { headers?, bodies? }` on table methods, `cursorPagination`, `rpc`, `fn` and `request` (never sent to the server). `mode: 'perRequest'` (default) logs only those calls, `'all'` every call (except `log: false`), `'off'` none; an unknown mode means `'perRequest'`. Off by default and silent without a logger; the main entry only gains the types (`LogEntry`, `LogMode`, `LogOption`, `RequestLogger`).

One entry per HTTP attempt, so a 401 refresh retry or a `retry` attempt gets its own entry: method, URL with redacted query, status (`null` without a response), duration, sanitised request id, 1-based attempt, error `code` / `errorCode`, plus redacted headers and bodies when asked for. Redaction cannot be switched off: sensitive header names (by pattern), the tenant header and the URLs in URL-valued headers (`Location`, `Content-Location`, `Referer`, `Origin`, `Link`, `Refresh`); sensitive body and query keys at any depth (also bracketed and comma-joined `anyOf` keys); `key=value` pairs in URL fragments; filter groups (`or`, `and`) and `select` embed filters naming a sensitive column; credentials in URLs. Bodies are cut at 2048 characters (`maxBodyLength`); binary, multipart and stream bodies are described, not read. The sink runs inline; a sink, or a hand-written logger, that throws or rejects never changes a request result.
